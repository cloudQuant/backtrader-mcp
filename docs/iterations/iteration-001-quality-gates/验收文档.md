## 1. 验收原则

验收必须从本仓库根目录执行，Python 命令使用用户的 Anaconda base 环境。通过标准
以命令退出码和机器可读/可复查输出为准，不以 CI 图标、pytest 进度点或文档声明替代。

## 4. 失败处置

- A1/A2 失败：只应用受选定 formatter 驱动的机械变更后重试。
- A3 失败：定位到具体类型边界，修复或增加精确类型；禁止将 CI 恢复为 advisory。
- A4-A6 失败：修正发现顺序或测试 extra，不改变 MCP 生产运行时注册规则。
- A7-A9 失败：冻结进入下一迭代，先修复失败单元并完整重跑。
- A10 失败：修复 job、依赖或工件路径后重跑 A9，不能将脚本重新降为手工门禁。
- A11 失败：以实际可执行配置为准同步文档，重新审阅。
- A12 失败：冻结发布字段扩展，修复 field allowlist 或传递链路后从 parser 到运行时完整重跑。
- A13 失败：保持公开运行时兼容性为阻断项；修复受控 adapter、indicator 或清理路径后重跑隔离完整套件，禁止缩窄 test extra 来掩盖失败。
