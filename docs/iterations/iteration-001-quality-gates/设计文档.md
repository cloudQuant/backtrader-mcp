# 迭代 001：设计文档

## 1. 设计原则

- **最小生产面**：测试使用的 Backtrader 只属于 `test` optional extra，绝不加入
  主 `dependencies`，保留 MCP 服务器对注册 runtime root 的信任边界。
- **单一事实来源**：Ruff 同时负责 lint 与 format；质量说明和 CI 命令以实际配置为准。
- **失败可诊断**：运行时发现失败要列出检查过的候选，不把环境缺失伪装为回测失败。
- **类型修复不改变运行时策略**：优先使用精确联合类型、局部变量和 `cast`，而非
  broad `Any`、忽略注释或更改安全校验流。
- **已发布字段必须端到端闭环**：JSON Schema、parse allowlist、不可变 canonical
  表示、scaffold 与 worker 配置不能各自接受不同字段集合。

## 2. StrategySpec 契约闭环

`StrategySpec.parse()` 的 canonical allowlist 增加 `slippage`。既有 `risk` 解析、
`slippage_value`、`as_dict()` 和 scaffold 的实现保持为单一值来源；本轮不改变滑点
数值语义或默认值。

dataclass 增加 schema 已发布的 `ir`、`extensions`、`non_goals`、`undecided` 字段。
对象型字段在进入 immutable contract 前使用 canonical JSON 进行深拷贝和 JSON 值
校验；字符串数组必须逐项为字符串。这样它们会自然出现在 `as_dict()` 和
`spec_hash` 中。

每个 normalized feed 显式保留 `dataset_feed`，schema 的 `Feed` 定义也增加该可选
属性。已有 `dataset_feed_names` 仅可由 canonical feeds 导出，不能再作为唯一的、
未哈希执行配置来源。

新增回归覆盖：

1. 顶层 `slippage: 0.1` 能通过 parse 和 schema 验证；
2. `StrategySpec.parse(spec.as_dict()).as_dict()` 保留滑点、四类可选元数据和非默认
   feed mapping，且改变任一执行/元数据字段会改变 `spec_hash`；
3. schema 验证 canonical output，保证 schema-valid 客户端能提交非默认 mapping；
4. 生成的策略文件保留滑点和 mapping，并在由固定 Backtrader runtime 执行时使
   broker 的滑点配置和 feed binding 可观察。

## 3. 运行时发现

`tests/conftest.py` 的 `_backtrader_runtime_root()` 将改为如下优先级：

```text
BACKTRADER_MCP_TEST_RUNTIME_ROOT
  -> 仓库父目录的相邻 checkout 候选
  -> 已安装 backtrader 模块所在的包根目录
  -> 明确的 RuntimeError（含候选说明）
```

候选验证统一采用 `candidate / "backtrader" / "__init__.py"`；环境变量路径既可指向
包根目录，也可指向包含 `backtrader/` 的运行时根目录。测试会覆盖三种分支：显式
路径优先、已安装包回退、无效显式路径失败。

`pyproject.toml` 的 `test` extra 固定为经本轮实测的
`backtrader==1.9.78.123`。CI 继续只安装 `".[test]"`，由该 extra 保证完整 checkout
可重现；产品 wheel 的主依赖列表维持不变。

## 4. 公开 Backtrader CSV adapter 兼容性

`BacktraderCSVData`、`YahooFinanceCSVData` 和 `MT4CSVData` 在公开
`backtrader==1.9.78.123` 的初始化阶段把 `dataname` 当作路径处理，不能接收内存
`StringIO`。因此，受控 worker 在需要改写 canonical CSV 为 adapter 专用表头/日期格式
时，改用私有、权限收紧的临时 CSV 路径作为 `dataname`。

- 临时文件只由 `feed_runtime` 使用 `mkstemp` 创建，默认权限为 owner-only；其内容
  仅来自已经验证且已物化的 canonical CSV。
- `_build_feed` 返回其创建的临时路径；`run_materialized_backtest` 用 `try/finally`
  在正常结果、Backtrader 异常或策略异常时逐一删除。
- 已是 canonical path 的 `GenericCSVData` 和内存 dataframe 的 Pandas adapter 不创建
  临时文件。临时文件不进入 CAS、不写配置的 source/target root，也不出现在运行结果。
- 验收在隔离 target 中强制导入 PyPI `backtrader==1.9.78.123`，而不是依赖相邻 fork；
  完整十四格矩阵同时覆盖三个路径型 CSV adapter。

`multi_indicator_system` 使用 `bt.indicators.RSI_Safe`，而不是默认关闭除零保护的
`RSI`。这只定义原本未定义的零损失窗口：正常 RSI 计算保持不变，零分母按 Backtrader
的安全语义映射为有限值，从而使 `runonce` 和 `runnext` 可以完成同一策略模板。

## 5. 质量门禁收敛

```mermaid
flowchart LR
    A[checkout] --> B[install .[test]]
    B --> C[Ruff lint]
    B --> D[Ruff format check]
    B --> E[pytest + coverage]
    B --> F[mypy]
    E --> G[independence audit]
    B --> I[wheel build + clean-install acceptance]
    C --> H[required CI result]
    D --> H
    F --> H
    G --> H
    I --> H
```

- CI lint job 安装 Ruff 并运行 `ruff check`、`ruff format --check`。
- pre-commit 改为 `ruff` + `ruff-format`，移除 Black hook，避免两个 formatter 竞争。
- CI typing job 移除 `continue-on-error`；安装依赖时保留 constraints 并显式安装 mypy。
- 新增 Linux-only distribution job：安装 `.[test]` 后执行
  `scripts/run_acceptance.py --matrix all --require-no-skills --require-no-agent`，通过
  `tee` 写出 JSON；shell 使用 `pipefail`，并以 `if: always()` 上传结果工件。
- `CONTRIBUTING.md`、README、CHANGELOG 和 `pyproject.toml` 同步到最终的实际门槛。

## 6. 类型修复方式

按错误聚类而不是全局压制：

| 区域 | 处理方式 |
| --- | --- |
| AST visitor | 为 `AsyncFor`/`AsyncWith` 建立与同步节点相同的共享处理路径，并使用 `ast.stmt`/`ast.expr` 的正确联合。 |
| SQLite state | 避免用实例方法名作为类型；以显式 `Callable` 或实际数据类型表达。 |
| 合同和数据解析 | 在 dict 索引前验证/收窄键与 `isinstance` 的 class-info。 |
| 子进程、doctor、CLI | 将可能为 `None` 的 pid/路径/记录在调用前收窄；拆分变量避免不同类型复用。 |
| 资源文件/MCP SDK | 用与 `importlib.resources` 和当前 SDK API 兼容的最小类型边界表达；运行时协议测试仍作为行为证据。 |

每一类修复至少对应一个既有测试的重跑；若出现行为风险，新增回归测试。

## 7. 覆盖率策略

先运行完整 pytest 获得分支覆盖率。只有在结果达到 80% 后才能把
`fail_under` 设为 80；否则优先为已存在但未覆盖的产品逻辑添加小而有行为断言的
测试，直到门槛可稳定通过。禁止通过扩展 `omit`、降低报告范围或仅更新文档来制造
表面通过。

## 8. 风险与回滚

| 风险 | 缓解 |
| --- | --- |
| PyPI Backtrader 与相邻 fork 的行为差异 | CI 使用声明的公开包；相邻 checkout 仍作为本地优先候选，并在十四格矩阵中验证。 |
| adapter 临时文件泄漏或污染受管目录 | 只用私有临时路径并由 `finally` 清理；在公开运行时矩阵中同时覆盖成功/失败路径。 |
| Ruff 格式化造成大范围 diff | 仅接受 formatter 的机械变更，审查后运行完整测试和 diff check。 |
| 旧 SDK 类型信息不完整 | 将类型适配局限在边界，不以 `Any` 扩散到业务安全逻辑。 |
| 覆盖率提高暴露遗漏 | 先补测试并保留现有 14 格分发验收，不能用排除规则规避。 |
