# 迭代 010：授权可信分离与安全加固

## 背景

2026-08-15 安全审计的 HIGH/MEDIUM 结论：审批"人机分离"的完整性依赖
"宿主不给 Agent 本地 shell"这一未声明假设；nonce 从未被校验（反重放只靠可选
幂等键）、exp 判定宽松、verify 对畸形 payload 不够严格；run-result 契约的
字符串字段无约束（本地文件外带通道 + Markdown 注入）；fcntl 顶层导入使
Windows 完全不可运行；rlimit 应用/跳过无任何记录；供应链传递闭包无哈希锁。

## 目标

1. **审批身份审计 + 宿主假设声明**：`approve` 生成的审批记录与审计行携带
   审批者 OS 身份（uid/username，POSIX；非 POSIX 记录可用字段）；README 安全
   模型显式声明"审批安全取决于宿主不授予 Agent 本地命令执行能力"及强化选项
   （sudo 门控/独立账户/审批守护进程）。
2. **令牌硬化**：verify 严格校验 payload 为 dict、`exp <= now` 即失效、
   `iat` 必须在 ±300s 时钟偏移窗内；nonce 加入 SQLite 一次性台账
   （issue 登记、verify 原子消费），重放与伪造一律 Forbidden。
3. **结果契约收紧**：worker 校验 `strategy_feed`/`constructed_class`/
   `registered_class` 必须匹配 identifier 正则（`^[A-Za-z_][A-Za-z0-9_.]{0,127}$`）
   且非空；报告渲染对 extra metric 名做 Markdown 转义。
4. **Windows 可运行**：locks.py 平台分支（msvcrt.locking 回退），移除顶层
   fcntl 导入；process_control 的 nt 分支成为可执行代码（Windows 实机验证仍
   不承诺）。
5. **rlimit 可观测**：worker 记录每个限额的应用/跳过结果到 job 行与 audit。
6. **供应链哈希锁**：constraints 文件包含完整传递闭包的 --generate-hashes
   锁定。

## 非目标

- 独立审批守护进程/硬件令牌（本迭代为文档化强化选项，实现留待宿主策略
  明确后）；Windows CI 与实机验证（011）；TOCTOU 加固（O_NOFOLLOW）。

## 验收标准

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| R1 | 审批身份 | approve 审计行含 approver uid/username（POSIX 断言） |
| R2 | 令牌硬化 | 重放同一 token 第二次 verify 抛 Forbidden；exp==now 失效；iat 超窗拒绝；数组 payload 拒绝 |
| R3 | 结果契约 | 非 identifier 类名/feed 名被拒；registered_class 空串被拒；metric 名含 Markdown 特殊字符被转义 |
| R4 | Windows | 非 POSIX 下 locks 走 msvcrt 分支（monkeypatch 测试）；POSIX 行为不变 |
| R5 | rlimit | worker 运行后 job 行含 resource_limits_status；audit 记录 |
| R6 | 供应链 | constraints 全闭包含哈希；`pip install -c constraints` 可复现安装 |
| R7 | 回归 | 全量 pytest ≥80%；ruff/mypy/协议测试通过；清洁 wheel 14 格矩阵通过 |

## 风险与控制

- **nonce 台账引入状态依赖**：TokenSigner 无 state 时退化为无台账行为
  （仅测试/独立 CLI 路径）；产品路径（service 构造）恒传入 state。
- **iat 窗口**：±300s 容忍时钟偏移，正常签发-验证间隔远小于该窗口。
- **结果契约收紧的兼容性**：既有 14 格矩阵的候选产物类名/feed 名均符合
  identifier 正则（回测矩阵锁定）；不合规产物从"接受"变为"validation
  失败"，属刻意收紧。
- **msvcrt 分支无实机验证**：以 monkeypatch 平台名测试分支选择逻辑；
  README 如实声明 Windows 实机验证仍未记录。
