# 迭代 008：作业状态机硬化与监督闭环

## 背景

2026-08-15 审计的作业生命周期维度发现一组相互关联的正确性缺陷，全部落在本迭代：

- **状态迁移无 CAS 守卫**：`StateStore.update` 无前置条件，cancel 与 worker 的终态
  写入互相覆盖——已取消的作业可复活为 SUCCEEDED（LLM 会把被取消的回测当有效
  结果）；`get_run_status` 的 stale-read 可把刚成功的作业覆写为 ORPHANED，结果
  永久不可读。
- **无服务器侧监督**：活性/超时检测全靠拉取式轮询；worker 被 SIGKILL 后候选进程
  （独立 session）无墙钟上限地存活；心跳 ~1Hz 写入但全库无人读取（死代码）；
  RLIMIT_CPU 封不住 `sleep` 循环。
- **并发闸门非原子**：count-then-insert，跨 run-plan 并发可超额；幂等键跨 plan
  碰撞会在报错前留下重复运行中的作业。
- **错误无结构化分类**：资源超限被杀（负数退出码）与策略 bug 同为 FAILED，LLM
  无法机器区分；worker 内部异常（如 SQLite 锁超时）只落 supervisor 日志。
- **存储与诊断缺口**：作业产物与记录无保留策略；doctor 不覆盖作业子系统。

## 目标

1. **CAS 状态转移**：`StateStore.update` 增加 `expected` 前置条件（与读-改-写同一
   事务，`BEGIN IMMEDIATE`）；全部 job 状态写入带前置条件。仲裁规则：**终态一旦
   持久化永不被覆写；CANCEL_REQUESTED 一旦可见，SUCCEEDED/FAILED/TIMED_OUT 写入
   全部失效**。
2. **监督闭环**：服务器内建 watchdog 守护线程（仅在 `serve` 启动，CLI 不启动）：
   消费 heartbeat_at 判定失速、独立执行墙钟超时、清理孤儿作业的候选进程组。
   `get_run_status`/启动恢复的 ORPHANED 写入改为 CAS，杜绝 SUCCEEDED→ORPHANED
   翻转。
3. **原子并发闸门**：`start_strategy_run` 的并发计数与作业创建放入全局文件锁；
   幂等键在锁内复查，消除跨 plan 幂等碰撞产生的重复作业；语义保持"拒绝而非
   排队"（文档化），拒绝错误附可操作建议。
4. **error_kind 结构化**：job 增加 `error_kind ∈ {user_strategy, resource_limit,
   timeout, validation, infrastructure, cancelled, orphaned}`；worker 按退出码
   （负数=信号）与阶段分类；cancel/watchdog 分类；worker 顶层异常兜底写入
   infrastructure 错误。
5. **保留策略与诊断**：`clean --kind jobs --before ISO`（仅终态作业，删行+删
   目录+审计）；清理后 WAL checkpoint；`doctor` 增加只读 jobs 统计段（状态计数、
   最长活跃作业、WAL 大小），无 state 时不初始化任何文件。
6. **输入加固**：`timeout_seconds` 拒绝 bool（`True is int` 漏洞）。

## 非目标

- FIFO 队列实现（保持"拒绝而非排队"，README 明确文档化）。
- 启动恢复移出服务构造函数、PID start-time 绑定、Windows 实机验证——心跳监督
  已缓解 PID 复用后果，残余风险在 README 如实声明。
- 派生管道、存储 GC 扩展（CAS/drafts）、覆盖率宇宙修复（iteration-009/011）。
- OS 沙箱与多主机分布式事务（既有声明不变）。

## 验收标准

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| R1 | CAS 更新 | `update(expected=...)` 前置条件失败抛 Conflict 且不写库；成功路径行为不变。 |
| R2 | 终态仲裁 | worker 终态写入在 CANCEL_REQUESTED/终态下被抑制；cancel 在终态已写入时返回 already_terminal 且不杀进程；SUCCEEDED 作业在 worker_pid 已死时不被覆写为 ORPHANED。 |
| R3 | watchdog | 心跳失速（阈值 15s）→ 杀 worker+候选进程组 → TIMED_OUT；worker 死亡 → ORPHANED 且候选进程组被清理；墙钟超时（started_at+timeout+宽限）→ TIMED_OUT；终态作业不被触碰；watchdog 仅在 serve 进程运行。 |
| R4 | 并发闸门 | 并发名额满时 Conflict 且附 list_jobs 建议；同幂等键跨 plan 并发不产生重复作业。 |
| R5 | error_kind | 负数退出码归 resource_limit（含信号名）、校验失败归 validation、策略异常归 user_strategy、取消归 cancelled、孤儿归 orphaned；worker 崩溃兜底写 infrastructure。 |
| R6 | 保留与诊断 | `clean --kind jobs --before` 只删终态且日期早于 before 的作业（行+目录），active 保留；doctor 有 state 时输出 jobs 段、无 state 时不创建任何文件。 |
| R7 | 输入加固 | `prepare_strategy_run(timeout_seconds=True)` 抛 InvalidRequest。 |
| R8 | 回归 | 全量 pytest ≥80% 覆盖率；ruff/mypy/协议测试通过；清洁 wheel 14 格矩阵通过（worker 全部变更经真实子进程回测验证）。 |

## 风险与控制

- **worker 路径变更影响全部真实回测**：14 格验收矩阵 + 既有 jobs/recovery 测试
  是主要回归网；worker 的 CAS 抑制路径用可注入的纯函数与状态级测试覆盖。
- **watchdog 与 worker 的写竞争**：全部 watchdog 写入带 CAS（expected ACTIVE），
  与 worker 终态写入互斥；两者都失败时以读到的最终状态为准。
- **PID 复用残余风险**（无 start-time 绑定）：心跳失速判定兜底；README 安全模型
  声明该残余风险。
- **doctor 只读性**：jobs 段用 SQLite `mode=ro` URI 打开，不创建任何文件；
  既有的 doctor 只读回归测试锁定。
