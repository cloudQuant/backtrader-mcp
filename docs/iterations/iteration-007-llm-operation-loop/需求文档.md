# 迭代 007：LLM 操作闭环与上下文预算

## 背景

2026-08-15 的六维行业最佳实践审计（MCP 协议、安全、数据层、作业生命周期、测试工程、
量化能力）确认了产品在契约、安全与质量门禁上的扎实基线，同时发现一组直接伤害 LLM 可用
性的缺陷，全部属于本迭代范围：

- `get_catalog_snapshot` 每次调用返回约 315 KB（约 8-9 万 token）的 1155 条目录记录，
  无截断、分页或过滤，且 README 的宿主首次验证流程要求每个宿主调用它。
- LLM 无法通过 MCP 读取任何 per-job 日志（唯一入口是本地 CLI），失败作业的 traceback
  对 LLM 不可达，调试闭环断裂；`recover_job` prompt 要求"检查日志"但 MCP 侧无通道。
- 无作业枚举工具：LLM 丢失 job_id 即永久失去对作业的可见性，并发名额被不可见的作业
  占满时无法自助排查。
- 全部 26 个工具零 annotations、描述全部为一行式；宿主无法按只读/破坏性提示呈现工具。
- 错误契约未接线：`sanitize_for_client` 与稳定错误 `code` 只在 CLI 生效；MCP 边界上
  LLM 拿到的是 `Error executing tool X: <原始消息>` 扁平文本，绝对路径不脱敏、
  `code` 丢失，与 `errors.py` docstring 和 CHANGELOG 的声明矛盾。
- `search_strategy_catalog` 无分页元数据（total/has_more/next_offset）、空结果无指引、
  未知 archetype 错误不枚举合法值。
- `list_strategy_templates` 只有 resource 没有工具，README 却以工具口吻描述。
- 长作业仅有轮询：`get_run_status` 不提供 elapsed/eta 派生信息，`run_backtest` prompt
  不写轮询节奏，LLM 只能盲目高频轮询。

## 目标

1. `get_catalog_snapshot` 默认只返回 header（计数/哈希/溯源，含
   `extensions.entry_count`），`include_entries=true` 时返回带分页元数据的有界页；
   默认响应从约 315 KB 降到 1 KB 以下。
2. 新增只读工具 `get_run_logs(job_id, tail_bytes)` 与资源
   `backtrader-mcp://jobs/{job_id}/logs`：有界尾部读取、绝对路径脱敏、job_id 格式
   强校验（拒绝路径穿越）；`get_run_status` 返回 `log_uri`。
3. 新增只读工具 `list_jobs(state, limit, offset)`：按状态过滤（含 `active` 伪状态）、
   分页元数据、按创建时间倒序，摘要字段与 CLI `list --kind job` 一致。
4. 全部 29 个工具补齐 `readOnlyHint`/`destructiveHint`/`idempotentHint`/
   `openWorldHint`/`title` 注解；关键工具描述增强（指向 JSON Schema 契约、说明返回
   结构与错误后如何继续）。
5. MCP 边界错误契约：`ProductError` 支持可选 `suggestion`；新增
   `as_client_text()`（`[code] 脱敏消息` + `Suggestion: …`）；server 工具层统一
   捕获 `ProductError` 转结构化文本、其余异常经 `sanitize_for_client` 脱敏后返回；
   `contracts/{schema_name}` resource 错误枚举允许值。
6. `search_strategy_catalog` 增加 `offset` 参数与 `total`/`has_more`/`offset` 分页
   元数据；空结果返回可操作指引与合法 archetype 列表；未知 archetype 错误枚举合法值。
7. `list_strategy_templates` 注册为 MCP 工具（resource 保留）。
8. 轮询辅助：`get_run_status` 派生 `elapsed_seconds`/`eta_bound`/`log_uri`；
   `run_backtest` prompt 写明轮询节奏与 terminal 状态集合；`preview_dataset` 补
   `truncation_message` 指引。
9. 协议测试（隔离 mcp==2.0.0 target）由 12/26 工具子集断言升级为 29 个工具、10 个
   资源的全量集合断言，并新增错误路径注入与注解断言。

## 非目标

- 作业状态机 CAS 守卫、watchdog 监督线程、并发闸门原子化（iteration-008）。
- 数据管道流式化、refresh 增量、SQLite 连接治理、存储 GC（iteration-009）。
- 审批可信分离、nonce 反重放、result 契约字符串约束、Windows 可运行性
  （iteration-010）。
- 覆盖率宇宙修复、stdio 传输 E2E、Python 3.14 上界、hypothesis 性质测试
  （iteration-011）。
- 比较政策单一来源、derive 管道修复、analyzer 白名单（iteration-012）。
- 不引入 MCP Tasks 扩展、不做任何宿主 UI 集成；SDK 版本范围维持 `>=2.0.0,<2.1`。

## 验收标准

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| R1 | 快照瘦身 | 默认 `get_catalog_snapshot` 响应不含 `entries`、含 `extensions.entry_count=1155`、序列化 <1 KB；`include_entries=true` 返回有界页与 `pagination.total/has_more/truncated`；limit/offset 越界被拒。 |
| R2 | 日志通道 | `get_run_logs` 返回有界尾部与 `truncated` 标记，内容绝对路径脱敏；非法 job_id（含 `../` 穿越）被拒；资源 `backtrader-mcp://jobs/{id}/logs` 可读；`get_run_status` 含 `log_uri`。 |
| R3 | 作业枚举 | `list_jobs` 按状态（含 `active`）过滤、倒序、分页元数据正确；空结果 `jobs=[]`。 |
| R4 | 工具注解 | 协议测试断言全部 29 个工具：只读工具 `readOnlyHint=true`，`apply_strategy_changes`/`cancel_strategy_run` `destructiveHint=true`。 |
| R5 | 错误契约 | 错误注入协议测试：`is_error=true` 且文本含 `[invalid_request]` 与 `Suggestion:`；`contracts/{schema_name}` 未知名错误枚举 7 个允许值；无绝对路径泄漏（`<path>` 替换生效）。 |
| R6 | 搜索分页 | `search_strategy_catalog` 返回 `total/has_more/offset`；空结果含 `suggestions.valid_archetypes`；未知 archetype 错误枚举合法值。 |

## 风险与控制

- **服务签名变更的兼容性**：`get_catalog_snapshot`/`search_strategy_catalog` 增加参数
  均为带默认值的新增参数，旧调用兼容；`get_catalog_snapshot` 默认不再返回 `entries`
  是刻意的不兼容（README 明确宣传条目经搜索/分页获取），以全量回归与验收矩阵锁定。
- **工具数量从 26 增至 29**：协议测试由子集断言升级为全量集合断言，防止误删/改名
  回归。
- **日志内容脱敏与可调试性的权衡**：绝对路径替换为 `<path>` 后 LLM 仍可依据相对路径、
  行号与异常类型定位；`tail_bytes` 上界 25000 与默认 8000 控制单次响应体量。
- **`elapsed_seconds` 依赖服务器时钟**：仅作轮询辅助提示，不写入 run-manifest、
  不参与任何哈希绑定或比较判定，时钟偏差不影响契约。
- **MCP SDK 2.0.0 行为依赖**：工具异常被 SDK 包装为
  `Error executing tool X: <text>` 的 `isError` 结果（已核实 SDK 源码）；错误契约
  在异常文本层实现，协议测试在隔离 target 上锁定该行为。
