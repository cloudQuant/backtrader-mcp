# 迭代 007：LLM 操作闭环与上下文预算设计

## 架构决策

1. **错误契约在异常文本层实现**。mcp 2.0.0 SDK 将工具抛出的任意异常包装为
   `ToolError("Error executing tool {name}: {e}")` 并以 `CallToolResult(isError=True)`
   返回（`mcpserver/tools/base.py`、`mcpserver/server.py:415-424` 已核实）。因此
   结构化的客户端文本由异常的 `str()` 承担：`ProductError` 新增
   `as_client_text()`，server 工具层用统一包装器把 `ProductError` 与非产品异常分别
   转换为携带结构化/脱敏文本的 `ClientToolError`。包装器放在 `errors.py`（可在
   默认环境单测），`server.py` 只做薄应用。
2. **快照瘦身用"header/entries 分离 + 分页"而不是字符串截断**。截断 JSON 会破坏
   可解析性；分页元数据（total/has_more/offset/truncated）是结构化数据的正确模式，
   与 `preview_dataset` 的既有 `truncated` 先例一致。
3. **日志通道以只读工具 + 资源双形态暴露**，读取在 `jobs.py` 内做路径强校验
   （`job_[0-9a-f]{32}` 正则），内容经 `sanitize_for_client` 脱敏——与产品
   "绝对路径不跨 MCP 边界"的既有声明一致。
4. **派生字段不进持久化**。`elapsed_seconds`/`eta_bound`/`log_uri` 在
   `get_run_status` 响应期计算，不写入 job 对象、不参与哈希绑定，规避时钟与契约
   漂移风险。
5. **注解以分组常量 + 逐工具 title 的方式补齐**，保证 29 个工具语义一致且可被协议
   测试全量断言。
