# 迭代 006：CloudQuant Backtrader 运行时来源限制

## 背景

MCP 的受控 worker 会执行由 `BACKTRADER_MCP_RUNTIMES` 注册的运行时。此前仅验证
`backtrader/__init__.py` 是否存在，测试 extra 还允许公开 PyPI `backtrader`。这不能保证
实际执行的引擎来自指定的
[`cloudQuant/backtrader`](https://github.com/cloudQuant/backtrader)。

## 目标

1. 产品依赖只声明固定 revision 的 `cloudQuant/backtrader`，不再声明公开 PyPI
   `backtrader==…` 回退。
2. `prepare_strategy_run` 与 `start_strategy_run` 只接受可证明来自 CloudQuant 仓库的
   runtime root。
3. `doctor` 要报告当前解释器中已安装 Backtrader 的来源：缺失、来源不可信时给出稳定的
   warning；已配置但不可信的 runtime 必须是 error。
4. 若 Backtrader 缺失，提供受控的 `install-backtrader` CLI 安装固定 CloudQuant
   revision；若已有其他发行版，保留该环境并输出警告，不静默覆盖。
5. 未显式设置 `BACKTRADER_MCP_RUNTIMES` 时，仅把已验证的已安装 CloudQuant 包自动注册为
   默认 runtime；显式 `{}` 仍表示不注册 runtime。

## 非目标

- 不自动替换或卸载用户已有的非 CloudQuant Backtrader。
- 不把“origin 指向 CloudQuant”升级为本迭代的工作区内容完整性证明；固定安装依赖的
  revision 用于可复现部署，外部源码 checkout 仍可使用该仓库的受支持 revision。
- 不在只读 `doctor` 路径中执行安装、写入 state 或修改用户目录。

## 验收标准

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| R1 | 打包依赖 | wheel 元数据允许 VCS direct reference，并固定 CloudQuant Git revision。 |
| R2 | runtime root | CloudQuant `origin` 通过；其他 GitHub fork、PyPI 包或无来源 root 被拒绝。 |
| R3 | 已安装包 | PEP 610 `direct_url.json` 的 VCS URL 或本地源路径的 Git origin 可证明 CloudQuant 来源。 |
| R4 | 安装命令 | 缺失时调用固定 Git requirement；已有不可信包只返回 `installed_backtrader_untrusted`。 |
| R5 | 运行边界 | prepare 与 start 均再次检查来源，不能利用预先准备的 run plan 绕过限制。 |
| R6 | 清洁验收 | 临时 wheel target 记录 `backtrader=1.3.0`、CloudQuant provenance、14/14 矩阵、协议与独立性检查。 |

## 风险与控制

- VCS direct reference 需要 Hatch 显式允许：以 wheel 构建验收和配置回归测试锁定。
- CloudQuant 完整入口在隔离 worker 的冷启动会加载可选的绘图、分析和扩展组件，可能超过
  60 秒运行窗口：候选进程使用该仓库提供的 `BACKTRADER_LIGHT_IMPORT=1`，并由受控运行时
  显式加载所需 feed/analyzer；清洁 14 格矩阵锁定这个兼容性与时限。
- 包根通常没有 `.git`：优先读取 PEP 610 provenance；本地 `file://` direct URL 再检查源
  checkout 的 `origin`。
