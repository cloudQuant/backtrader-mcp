# 迭代 009：流式数据管道与存储效率

## 背景

2026-08-15 审计的数据层维度确认：注册/派生管线把整份 CSV 物化 3 次
（raw bytes + 全文 str + 每行 dict 列表 + StringIO 再编码），64 MiB 输入峰值
RSS 约 0.7-1.2 GB，stdio 单进程同步执行期间全部工具阻塞；多 feed 对齐为每个
feed 建全量时间戳 set（最坏 +1.6 GB）；CAS 去重发生在全部计算之后；refresh
每次全量重哈希 4300+ 文件并以 1155 个独立事务写库；SQLite 连接从不关闭
（实测 2218 个 ResourceWarning）；存储无 GC；性能可观测性为零。

## 目标

1. **流式注册**：register_dataset 读源文件 2 遍（读入内存 + 读后一致性哈希），
   逐行规范化直接写入临时文件并同步计算规范内容哈希，不再构建全量 rows 列表
   与 StringIO 副本；峰值内存从 ~15-20x 降到 ~1.5x 文件体积（64 MiB 上限下
   约 100 MB）。
2. **源级去重前置**：相同源内容 + 相同规范化参数（column_map/extra_columns/
   adapter_options）复用既有注册（manifest 级查找），跳过重复解析。
3. **对齐检查流式化**：只物化 master feed 时间戳集合，其余 feed 流式求交计数；
   峰值从 Σ 全量 set 降到 O(master)。
4. **派生加固**：derive 的 float 解析失败转为带行号上下文的 InvalidRequest；
   派生输出强制 max_dataset_bytes 上限；sma/returns 保留线性扫描（文档化）。
5. **refresh 增量与批量写**：按文件 (mtime,size) 缓存跳过未变文件的哈希与 AST
   解析；catalog_entry 与缓存行改为单事务整体替换（replace_kind），一次 refresh
   一次提交，并清除已删除源文件的陈旧条目。
6. **SQLite 连接治理**：StateStore 每线程复用连接（threading.local），消除
   ResourceWarning 洪流；`_initialize` 保持幂等。
7. **存储 GC**：`clean --kind cas|drafts|approvals --before ISO`——CAS 回收未被
   任何 dataset manifest 引用且 mtime 早于 before 的对象；drafts 删除未被
   run_plan/job 引用且早于 before 的草稿（行+目录）；approvals 删除已消费或
   过期且早于 before 的记录；全部带审计与 WAL checkpoint。
8. **耗时打点**：register/register_local_dataset/derive/refresh/search/preview
   输出结构化 duration 日志；preview/inspect 的完整性哈希走进程内
   (inode,mtime,size) 缓存。

## 非目标

- list_target_tree 工具（012 与 changes UX 一并处理）；懒初始化预热；
  草稿文件级上限；derive 向量化（numpy/pandas 引擎）；多主机分布式事务。
- 不改动 canonical 内容格式与 dataset manifest 契约（既有哈希与 14 格矩阵
  保持有效）。

## 验收标准

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| R1 | 流式注册 | 64 MiB 输入的注册峰值 RSS < 300 MB（测试以较小文件断言内存放大比 < 3x 文件体积）；两次读保证源变更检测语义不变。 |
| R2 | 源级去重 | 相同文件+参数二次注册跳过解析（打点/行为断言），返回相同 feed_objects sha256。 |
| R3 | 对齐流式 | 3 feed 对齐的内存仅物化 master 集合（行为断言 + 单测），overlap 数值与旧实现一致。 |
| R4 | 派生加固 | 坏值报 InvalidRequest 含行号；超限输出被拒。 |
| R5 | refresh 增量 | 无变更 refresh 不重哈希文件（缓存命中断言）；陈旧 catalog_entry 被清除；写入为单事务。 |
| R6 | 连接治理 | 全套件 ResourceWarning 归零（或仅剩与 SQLite 无关者）；并发（watchdog 线程）读写正确。 |
| R7 | 存储 GC | 三种 clean 只删目标对象且留痕；CAS 引用完整性正确（被引用对象绝不删除）。 |
| R8 | 回归 | 全量 pytest ≥80% 覆盖率；ruff/mypy/协议测试通过；清洁 wheel 14 格矩阵通过（数据管线变更经真实回测验证）。 |

## 风险与控制

- **canonical 字节级兼容**：流式写出与旧 `_encode_rows` 逐字节一致（同一 writer
  参数）；以既有数据集哈希回归与 14 格矩阵锁定；任何输出差异视为回归。
- **源级去重的正确性边界**：规范化是 (源内容, 参数) 的确定性函数；去重只复用
  规范产物，feed 级 manifest 仍按调用重建，不同 feed 描述符不会互相污染。
- **哈希缓存的安全边界**：缓存仅用于 preview/inspect 的完整性回显；worker 与
  令牌校验路径继续使用无缓存 file_hash。
- **replace_kind 的原子性**：单事务 DELETE+批量 INSERT；refresh 期间 search
  的读连接只会看到旧或新快照（SQLite 事务隔离），不会看到中间态。
