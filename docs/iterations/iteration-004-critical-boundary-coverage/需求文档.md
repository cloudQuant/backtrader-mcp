# 迭代 004：关键控制边界的覆盖率门槛提升

## 1. 背景与问题

迭代 003 全量测试的真实 branch coverage 为 76.33%，配置门槛仍为 75%。审计发现总数
达标掩盖了三个高价值边界的不足：

| 模块 | 当前覆盖率 | 风险 |
| --- | ---: | --- |
| `audit.py` | 16% | 禁止 sibling import、父级相对 import 与 `eval`/`exec` 的独立性审计几乎没有恶意/失败路径测试。 |
| `cli.py` | 40% | 本地 approve、list/show/logs/clean 是唯一的本地控制面，错误输出、确认语义和 JSON 行为覆盖不足。 |
| `reports.py` | 64% | metrics 的类型/有限数、null、浮点容差、extra metrics 和报告渲染是回测结果可信性的边界。 |

因此本轮不以排除或阈值降低制造数字，而为这些真正的行为补回归，并将项目 gate 提高到
80%。

## 2. 目标

- 将全局 branch coverage 的 fail-under 从 75% 提升至不低于 80%，且本地实际覆盖率达到
  80% 以上。
- 为独立性审计的所有检测类型和 clean result 增加文件级测试。
- 为 CLI 的控制面子命令、确认拒绝、ProductError JSON 与日志/清理路径增加用户可见行为
  测试，不通过直接调用私有 state 绕过 CLI。
- 为结果 metrics/compare/render 的负向和边界路径增加契约测试，确保错误保持
  `InvalidRequest`，hash 与 Markdown 输出稳定。

## 3. 范围

### 包含

- `tests/test_audit.py`、`tests/test_cli_control_plane.py`、`tests/test_reports_contract.py`
  及必要的现有测试扩充。
- `pyproject.toml`、README、CONTRIBUTING、CHANGELOG 与本目录三份文档中的 coverage gate
  同步。
- 正/负向审计、CLI 和报告测试；完整 suite、public Backtrader runtime、clean-room wheel
  验收。

### 不包含

- 扩大 coverage omit、降低分支配置、mock Backtrader 的实际 14 格运行、添加远程 transport
  或改变业务结果计算公式。
- 只为覆盖率把私有实现导出为 public API；测试应从现有 public CLI 或模块契约进入。
- 把对真实 Windows 的 E2E 缺口伪装为覆盖率改进。

## 4. 功能需求

| ID | 需求 | 优先级 |
| --- | --- | --- |
| R1 | 独立性审计必须分别证明 clean、sibling import、parent-relative import、dynamic execution 的 findings 格式与 status。 | P0 |
| R2 | CLI 必须覆盖 list/show/logs/clean/audit/recover，以及 approve 的非 TTY/错误 token/用户取消分支；所有 machine output 保持可解析 JSON。 | P0 |
| R3 | reports 必须拒绝缺失、非法 integer、bool、非有限 float、错误 null，并覆盖 exact/null/float/extra mismatch 与 markdown 输出。 | P0 |
| R4 | coverage 配置与所有用户文档都必须为 80%，不留“75%”的可执行说明。 | P1 |
| R5 | 现有审批、独立性、子进程和 clean wheel 行为不得因测试或 gate 提升而改变。 | P0 |

## 5. 完成定义

1. 实现前存在需求、设计和验收文档；
2. R1-R3 的正反例均在自动化测试中通过，且错误类型/结果 JSON 可复核；
3. `pytest -q` 实际 coverage 不低于 80%，并由 `fail_under=80` 强制；
4. Ruff、mypy、public Backtrader 全量 suite、clean-room wheel 14/14/protocol/independence
   全部通过；
5. 复审时不存在同等级、已发现但未覆盖的本地控制面或结果契约 P1。
