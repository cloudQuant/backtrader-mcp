# 迭代 003：受控子进程生命周期的可移植性边界

## 1. 背景与问题

迭代 002 的复审发现 `worker.py` 与 `jobs.py` 对受控 Python 子进程无条件传入
POSIX 专属行为：`preexec_fn`、`start_new_session=True` 和 `os.killpg()`。前两者在
Windows 上不适用，取消/超时路径也会因没有 POSIX process group 而不能保证终结已知
worker 或 candidate。当前文档没有把这类启动/取消失败呈现为明确的平台契约。

同时，两个最小环境都会替换子进程的 inherited environment。Windows 在使用
`CreateProcess` 时需要保留 `SystemRoot` 才能可靠启动 Python 及依赖 DLL；现有最小
环境未显式保留此键。

## 2. 目标

- 在一个小型、可单测的模块中统一 supervisor 与 candidate 的 platform-specific spawn、
  environment 和终止策略。
- POSIX 保持现有安全语义：独立 session/process group，candidate 才应用 resource
  limits，取消/超时优先 `SIGTERM`、再强制 `SIGKILL`。
- 非 POSIX（重点为 Windows）不得收到 `preexec_fn` 或 `start_new_session`；应请求
  Windows process group，保留 `SystemRoot`，并用 `Popen.terminate()`/`kill()` 终止已知
  child。没有 `Popen` 句柄的 supervisor/child PID 则使用本平台可用的定向终止。
- 提供可在 macOS/Linux 上运行的模拟平台单元测试，以及实际 POSIX cancellation/timeout
  回归，避免把无法在本机执行的 Windows E2E 宣称为已完成。

## 3. 范围

### 包含

- `src/backtrader_mcp/process_control.py`：platform-aware Popen kwargs、最小环境补全、
  Popen/PID 终止辅助函数。
- `worker.py` 的 candidate spawn/timeout/cancel 路径，`jobs.py` 的 supervisor spawn 和
  cancellation 路径。
- 对 POSIX 和模拟 Windows 分支的精确单元测试；README/CHANGELOG 与本轮三份文档。

### 不包含

- Windows runner 上的真实 14 格 Backtrader 运行、Job Object 子树管理、Windows resource
  limits 或将 Windows 标记为完全验收的平台。
- 放宽候选源码静态限制、添加 shell 调用、继承完整宿主环境或改变既有 token/审批流程。
- 为提高覆盖率而机械排除未覆盖代码；覆盖率提升另立迭代。

## 4. 功能需求

| ID | 需求 | 优先级 |
| --- | --- | --- |
| R1 | POSIX spawn 必须继续使用独立 session；candidate 仅在 POSIX 接收 resource-limit `preexec_fn`。 | P0 |
| R2 | 非 POSIX spawn 不得包含 `preexec_fn` 或 `start_new_session`，并在可用时使用 `CREATE_NEW_PROCESS_GROUP`。 | P0 |
| R3 | 所有受控最小环境在非 POSIX 下必须保留宿主 `SystemRoot`；不能因此继承任意敏感环境变量。 | P1 |
| R4 | Popen 终止在 POSIX 继续使用 group TERM/KILL；非 POSIX 必须先 `terminate()`，有界等待后再 `kill()`。 | P0 |
| R5 | 没有 Popen 句柄的恢复/取消路径必须根据平台终止已记录的 PID，而不是无条件调用 `killpg`。 | P1 |
| R6 | 模拟 Windows 与实际 POSIX 分支均有回归；现有取消、超时、crash recovery 和十四格验收保持通过。 | P0 |

## 5. 完成定义

1. 先存在本需求、设计和验收文档，才落地代码；
2. POSIX helper 的 options、环境和 TERM/KILL 行为由单元测试证明，既有真实 timeout/
   cancellation 行为不回退；
3. 模拟 Windows helper 不发出 POSIX-only kwargs，保留 `SystemRoot`，并走
   `terminate()`/`kill()`；
4. Ruff、mypy、完整 pytest、公开 Backtrader runtime suite 和 clean-room wheel 14/14
   均通过；
5. README/CHANGELOG 清楚表述“已适配的 spawn/termination 分支”与“未执行真实 Windows
   E2E”的边界，不将后者冒充为完成。
