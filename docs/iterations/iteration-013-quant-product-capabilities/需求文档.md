# 迭代 013：量化产品能力与收尾

## 背景

审计的量化维度剩余项与产品能力缺口：derive 产物的特征列对任何 feed 不可达
（precomputed_ml 闭环断裂，012 已 fail-fast 但仍无法用派生特征）；参数扫描
不可行（每个参数点需完整审批链）；alignment 契约声明了未实现的
left/explicit_asof 模式；模板缺 notify_order/sizer/订单类型范式；MT5 秒级
数据被静默截断；LLM 无法构造 expected_target_hashes（无只读目标树工具）；
worker 子进程覆盖率无合并通道。

## 目标

1. **derive→precomputed 管道**：returns/sma 派生数据集默认丢弃 warmup 行
   （文档化确定性语义），派生列注册为 pandas_custom_lines 自定义 line；
   派生数据集可直接用于 precomputed_ml。
2. **参数扫描**：新 run_profile `parameter_sweep`：prepare 冻结参数网格
   （StrategySpec parameters 名 → 值列表），worker 逐组合执行候选，
   结果契约含逐组合指标与排名；单次审批覆盖全网格。
3. **alignment 收紧**：DataSpec alignment.mode 仅接受 `intersection`，
   left/explicit_asof 以明确错误拒绝（文档化未实现）。
4. **模板升级**：scaffold 增加 notify_order（成交记录与滑点观测）、
   order_risk 演示 bt.Order.Stop、sizer 示例；README 增加执行语义段
   （默认 FixedSize(1)、佣金双边百分比、无风险利率 1%、drawdown 正数
   语义、yahoo adj close=close、bar2edge 默认差异）。
5. **MT5 精度防护**：注册期拒绝 timeframe 细于 minutes 的 mt5_csv feed。
6. **list_target_tree**：只读 MCP 工具返回目标目录树（相对路径 → sha256），
   使 LLM 能合法构造 expected_target_hashes。
7. **子进程覆盖率通道**：worker 环境透传 COVERAGE_PROCESS_START（测试
   环境启用后 worker 度量自动落盘，合并自动化记录为后续项）。

## 非目标

- walk-forward、多主机、独立审批守护进程、Windows 实机验证、目录快照再
  生成脚本（均已文档化或属宿主决策）。

## 验收标准

R1-R7 对应目标；R8 全量回归 ≥80% + ruff/mypy/协议测试 + 14 格矩阵。
