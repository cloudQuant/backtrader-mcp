# 迭代 011：测试宇宙与发布工程

## 背景

审计的测试工程维度：覆盖率门槛基于缩减宇宙（omit worker/feed_runtime/
server，整树 76%）；stdio 生产传输路径零自动化测试；requires-python 无上限
（3.14 崩溃）；hypothesis 声明为零使用；无发布自动化、版本字面量硬编码
4 处；constraints 与 pyproject 无一致性校验；14 格矩阵每次 push 跑 9 次。

## 目标

1. **覆盖率宇宙修复**：feed_runtime 与 server 移出 omit（协议测试已实际
   覆盖）；worker 保持 omit（子进程执行，14 格矩阵端到端验证，注释说明）。
2. **stdio 传输 E2E**：子进程启动 `serve`，在管道上完成 initialize →
   tools/list → 一次 doctor 调用 → 关闭，断言 stdout 为合法 JSON-RPC。
3. **解释器上界**：`requires-python` 收紧为 `>=3.10,<3.14` 并有测试锁定；
   CI 矩阵维持 3.10-3.13。
4. **hypothesis 性质测试**：HMAC 令牌任意单字节篡改必拒；路径受限任意
   `..` 相对路径必拒；StrategySpec 任意字典要么通过要么稳定报错（不崩溃）。
5. **发布自动化**：tag 触发 release job（构建 wheel → 清洁验收 → 上传
   GitHub Release 资产）；CHANGELOG 最新版本条目与 `__version__` 一致性
   测试取代字面量。
6. **constraints 一致性**：测试断言 constraints 的 pin 落在 pyproject 依赖
   范围内。
7. **CI 效率**：矩阵测试标记 `acceptance`，test job 排除（-m "not
   acceptance"），distribution job 保持全量。

## 非目标

- Windows CI/实机验证；worker 子进程覆盖率合并（COVERAGE_PROCESS_START，
  复杂度高、收益有限，记录为后续项）；四宿主配置 CI 校验。

## 验收标准

R1-R7 分别对应上述目标；R8 全量回归 ≥80% 覆盖率 + ruff/mypy/协议测试 +
清洁 wheel 14 格矩阵通过。
